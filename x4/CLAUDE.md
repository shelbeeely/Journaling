# Keeping Watch X4 firmware: context for Claude Code

Companion firmware for Shelbee's Keeping Watch paper journals (monthly books + yearly Keeper, built by
the sibling `journal/` project). Target: Xteink X4 (ESP32-C3, no PSRAM, ~380 KB RAM, 16 MB flash,
800x480 1-bit e-ink, 7 buttons) on the FreeInk SDK (`../freeink-sdk`). Read README.md first.

## Layout
- `src/app.cpp` — every screen + the input loop + refresh policy. Screens draw into a 480x800 portrait
  `Canvas`; `render(sameScreen)` picks Fast (partial, no flash), Half (screen change) or Full (sleep).
- `src/core/` — `canvas` (1-bit drawing, rotation into the 800x480 panel buffer, bitmap text with a
  symbol-font fallback), `data` (day packs, check-in log, month stats, Pacific time), `font.h`.
- `src/gen/assets.*` — GENERATED by `tools/gen_assets.py` (bitmap fonts from Inter/Lora/DejaVu, and the
  same monoline icons the paper day page prints). Edit the script, never the output.
- `src/hal/hal.h` — the only hardware boundary. `hal_x4.cpp` (FreeInk, Wi-Fi AP + WebServer, deep
  sleep with timer wake) and `host/hal_host.cpp` (PC preview) implement it.
- `src/core/settings.*` — `/kw/settings.txt` (large text, bold, button remap, sleep and refresh timing); `app.cpp` reads every font through `fS()/fUI()/fB()/fXL()/fBody()/fTitle()` so large text is one switch. `src/gen/assets_large.*` is GENERATED by `tools/gen_large.py` (Inter only, so it builds without Lora). The button remap runs in `appMain` (`settingsMap`) and in `hintBar`, so labels follow. `host/test_settings.sh` tests it.
- `src/net/webpage.h` — the self-contained page served at 192.168.4.1 (hotspot) or the LAN address (PIN for anything private or changing).
- `src/core/net.*` — Wi-Fi modes (BUILD-PLAN section 19, N1): `/kw/net.txt` (saved networks, PLAIN-TEXT passwords: never uploaded, logged or shown), the `NetGuard` PIN and one-client rules, the `NetCtl` join state machine, and the answers for the page's `/api/info|unlock|net/*` calls. Portable, so `host/test_net.sh` runs the device's code on a simulated network (`host/hal_host.cpp`, env `KW_WIFI`). The radio and web server belong to the Wi-Fi screen: off until a mode is picked, freed on exit, and `host/test_off.sh` (audit of the source, the app's every exit, the radio log) proves nothing is sent anywhere or woken in the background. N2 (sync) changed it on purpose: the one allowed way out is the marked block in `hal_x4.cpp`.
- `src/core/sync.*` — Sync with Studio (N2): `/kw/sync.txt` (server, device token, `log=`), the plan (only bytes added since the last sync), the upload loop (3 KB chunks at an exact `X-Offset`, 409 resumes), and the plain-words failure messages. Portable: `host/test_sync.sh` runs it on a simulated Studio (`hal_host.cpp`, env `KW_SYNC`). `syncRun` has ONE caller: `syncGo` in `app.cpp`, on Confirm of the preview screen. Uploads `/kw/log/YYYY-MM.csv` only.
- `src/net/hostcheck.cpp` — the host name check the SDK's SecureClient lacks (`-Wl,--wrap=wolfSSL_UseSNI`, x4-tls only); `tls/hostcheck_test.sh` proves it on a PC. Never call `setInsecure()`.
- `tls/` — the sync build (`pio run -e x4-tls`: the SDK's SecureNet + wolfSSL, `tls/user_settings.h`), `heap_probe.sh` (wolfSSL heap in a real handshake, on a PC, run by CI), `hostcheck_test.sh` and `budget.py` (CI fails if less than 32 KB would be left with a TLS session open). The default `x4` image has no TLS: its Sync row says so.
- `tools/export_pack.py` — journal `out/m*/data.json` + content JSON → `sd/kw-update/` (never `kw/`, `me.txt` or `log/`). `src/core/update.cpp` moves it into `/kw` on boot.

## Rules that matter here
- Pixel changes: run `host/preview.sh` and look at the PNGs before and after. The host build is the
  fast loop; the device build is `pio run -e x4` (must stay `[SUCCESS]`).
- RAM: one 48 KB framebuffer (single-buffer mode). Keep big buffers static, never on the 16 KB loop
  stack. No exceptions (`qrcodegen` was patched to abort instead of throw).
- Sleep: CrossPoint's "off" drops GPIO13 and cuts the battery. We hold GPIO13 high through deep sleep
  so the RTC and the 4:31 a.m. timer keep working. Don't copy CrossPoint's power-off path.
- Privacy: packs contain her calendar events and the log holds health check-ins. Nothing leaves the
  device except over its own hotspot, or an explicit sync the user starts on the device over Wi-Fi they configured, to
  their own Studio account (BUILD-PLAN section 19; each category is opt-in, the log is off by default). No background sync,
  no analytics, no other cloud, no generative AI features.
- Data safety: the safety plan (`/kw/me.txt`) and the log (`/kw/log/`) exist only on the card. Nothing exported, uploaded or
  updated may overwrite or delete them (`host/test_update.sh` guards it).
- Accessibility: every new screen or line of text must work at Large and Bold (`preview.sh` renders `l_*`, `b_*`, `r_*` PNGs: look at them). Never draw a state as a thin stroke; never cut content with "..." in Large: page it. Nothing may time out on someone reading or typing slowly.
- Scope: calm and low-stimulation. No notifications, feeds or badges. Ask before adding a feature.

## Open work (in order)
1. Hardware bring-up: buttons (hold detection, power-button wake), refresh quality/ghosting, deep-sleep
   current, timer wake accuracy over a few nights, web page upload/download speed.
2. Dual boot with CrossPoint: menu item to boot the other OTA slot, and a way back (FreeInk RecoveryBoot).
3. Month switch on the device: a "Closing <month>" screen that walks through the Keeper handoff.
4. Routines as tickable items. Not planned: since the care split, paper is where routines are ticked and the X4 shows them as text.

- `src/core/focus.*` — Focus timer arithmetic + `/kw/focus.txt`; logs `focus_rounds` / `focus_interruptions` (keys are stable, the paper block relies on them). `host/test_focus.sh` tests it.

## The care split (approved 2026-09-28)
Paper: meds, meals, water, mood, work shift, routines, events, writing, safety plan (source of truth). X4: spoons **left**,
sleep, anxiety, shower, teeth, joy, texted, snack, plus custom check-ins. `ITEMS[]` keeps every old key (`med_am`, `med_pm`,
`prn`, `meal1-3`, `mood`) as `hidden` entries so old logs still read; do not rename or drop them. The two Keeper tiles on
This month ("Good-spoon days", "Avg sleep") must match `journal/handoff.mjs` (`journal/check-handoff.mjs` enforces it).
