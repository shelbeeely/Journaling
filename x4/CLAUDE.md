# Keeping Watch X4 firmware: context for Claude Code

Companion firmware for Shelbee's Keeping Watch paper journals (monthly books + yearly Keeper, built by
the sibling `journal/` project). Target: Xteink X4 (ESP32-C3, no PSRAM, ~380 KB RAM, 16 MB flash,
800x480 1-bit e-ink, 7 buttons) on the FreeInk SDK (`../freeink-sdk`). Read README.md first.

## Layout
- `src/app.cpp` — every screen + the input loop + refresh policy. Screens draw into a 480x800 portrait
  `Canvas`; `render(sameScreen)` picks Fast (partial, no flash), Half (screen change) or Full (sleep).
- `src/core/` — `canvas` (1-bit drawing, rotation into the 800x480 panel buffer, bitmap text with a
  symbol-font fallback), `data` (day packs, check-in log, month stats, Pacific time), `font.h`.
- `src/gen/assets.*` — GENERATED by `tools/gen_assets.py` (bitmap fonts from Inter/Lora/DejaVu, and the
  same monoline icons the paper day page prints). Edit the script, never the output.
- `src/hal/hal.h` — the only hardware boundary. `hal_x4.cpp` (FreeInk, Wi-Fi AP + WebServer, deep
  sleep with timer wake) and `host/hal_host.cpp` (PC preview) implement it.
- `src/net/webpage.h` — the self-contained page served at 192.168.4.1.
- `tools/export_pack.py` — journal `out/m*/data.json` + content JSON → `sd/kw-update/` (never `kw/`, `me.txt` or `log/`). `src/core/update.cpp` moves it into `/kw` on boot.

## Rules that matter here
- Pixel changes: run `host/preview.sh` and look at the PNGs before and after. The host build is the
  fast loop; the device build is `pio run -e x4` (must stay `[SUCCESS]`).
- RAM: one 48 KB framebuffer (single-buffer mode). Keep big buffers static, never on the 16 KB loop
  stack. No exceptions (`qrcodegen` was patched to abort instead of throw).
- Sleep: CrossPoint's "off" drops GPIO13 and cuts the battery. We hold GPIO13 high through deep sleep
  so the RTC and the 12:31 a.m. timer keep working. Don't copy CrossPoint's power-off path.
- Privacy: packs contain her calendar events and the log holds health check-ins. Nothing leaves the
  device except over its own hotspot, on request. No cloud, no analytics, no generative AI features.
- Data safety: the safety plan (`/kw/me.txt`) and the log (`/kw/log/`) exist only on the card. Nothing exported, uploaded or
  updated may overwrite or delete them (`host/test_update.sh` guards it).
- Scope: calm and low-stimulation. No notifications, feeds or badges. Ask before adding a feature.

## Open work (in order)
1. Hardware bring-up: buttons (hold detection, power-button wake), refresh quality/ghosting, deep-sleep
   current, timer wake accuracy over a few nights, web page upload/download speed.
2. Dual boot with CrossPoint: menu item to boot the other OTA slot, and a way back (FreeInk RecoveryBoot).
3. Month switch on the device: a "Closing <month>" screen that walks through the Keeper handoff.
4. Routines as tickable items (today they are shown, not logged).
